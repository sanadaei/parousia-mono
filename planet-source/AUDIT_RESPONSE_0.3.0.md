# 0.3.0監査への対応（0.3.1）

更新日: 2026-10-09。添付の監査を現行ソースと照合し、C1地域地形と静的水系の併用、全球地域viewと道路診断の接続を修正した。湖・海・内陸終端湖の自動化は、利用者の「水域の自動化は後に回す」を維持する。

この文書は0.3.1の対応記録。0.3.2で追加した単一の明示全球水系chart、中心線掘削上限と保存再検証、現在の第3段階の残項目は [GLOBAL_WATER.md](GLOBAL_WATER.md) と [ROADMAP.md](ROADMAP.md) に記録する。

## 実装した修正

| 指摘 | 変更と確認 |
|---|---|
| C1地形で河川・表流水格子を拒否 | 地形@3のC1基礎地形に静的河道・明示水位の水域・表流水/地下水格子を接続できる。元の基礎補間・既存@1/@2保存は維持 |
| 二次極値判定をC1へ流用できない | 切り取ったBezier制御点の包絡で河道周囲の基礎標高の下限を求める。境界上は格子カットごとに六次Bernstein多項式を作り、導関数の根で最小値を調べる。保存再開でも岸/水域を再検証 |
| 投影地域の線分参照が欠落 | `traceSurfaceSegment`を追加。有限地域と標本予算・座標計算を共通化。投影地域では固定間隔と中点から同じ全球場を参照し、未解決の水深をnullで保持 |
| 道路診断が投影地域で例外 | referencesがない場合の既定道路を空集合にし、明示した道路を診断できる。`unresolvedWaterSamples`と精度説明を返す。未知水深の点を乾いた進入路に数えない。投影地域の橋高指定にはworldIdに加えregionIdを要求 |
| 水位参照の双線形直呼び | 双線形側も`staticLevelAt`を使う。C1表流水格子では水位と基礎水深の六次極値を標本へ追加 |
| ファイル末尾のimport | water-modelの依存importを先頭へ移動 |
| 構築済み点列の再入力で極小区間を生成 | 元の点を優先し、1e-8m未満の距離差を持つ補助標本を統合。補助点の丸めで有効な点列を拒否する問題を回帰試験で確認 |

Bezier包絡は真の最小値以下の保守的な下限で、元パッチ全体ではなく切り取った矩形を評価する。一つの河道区間で65,536矩形を超える入力は明示的に拒否する。明示水域の内部矩形はその水位を使い、乾いた水際では基礎標高の下限を守った上でfreeboardを0まで緩和する。斜めの水域境界などで矩形包絡が厳しすぎる場合は、実際に接続可能な入力でも構築を拒否し得る。

**C1は基礎地形の契約。** 河床・岸は既存の三角形帯の連続な変形で、掘削後の地表全体の一次導関数が連続する保証はまだない。全球の投影viewは有限地域のcanonical格子を持たず、`connectSurfaceWater`への直接入力には対応しない。今回の地域C1水系接続を、全球水系接続の完了とは扱わない。

## 監査の説明を補正した点

- 全球水深は0ではなくnull、surfaceKindもunresolved。水域自動化の延期は利用者の指定であり、海面0を新たに仮定しない。
- sourceの表示曲線はreferencesに保持する。河道の構築には、折り返し/重なりを避けて一次流向骨格を使っている。D8の方向バイアスは残る。
- 分流拒否は任意のStrahler断面調整に対する制限。静的graph全体の分流禁止ではない。デルタの流量配分・自然さを実装したとも扱わない。
- 元セル/流域のnullは厳密な極点の扱いで、周辺の極域全体からメタデータを除去していない。
- 同一全球場を参照する窓/view間の値・勾配は一致する。独立した有限地域snapshot同士を結合する機能は別の未実装事項。
- surface-water builderは主に水面profileを解く。断面・メッシュと索引はwater-modelで構築/検証し、保存再開でも派生メッシュを再構築する。幾何生成/索引のコード分離は改善候補として残る。
