# 地域をまたぐ湖・海の共通参照

## 一つの水域を複数の地域から読む

connectGlobalSurfaceWaterCharts の sharedBaseWater に canonical-base-water@1 を明示すると、
基礎世界に既に保存された海面・湖・河川の水面を、全地域と地域間の隙間から共通参照する。
湖を地域ごとの別ポリゴンとして複製しない。水域IDと水位と標高基準は基礎世界の一組の定義を使う。
地域の河床掘削後の地盤に対して水深を再計算する。河口や水没した水路は高い水面が選ばれ、
同水位では基礎側の水域来歴が先になる。これは既存の惑星 Core / ページ参照と同じ優先順。

保存は従来の多地域schema @2に明示ポリシーを追加した新しいworldIdになる。
省略した旧保存の地域内の意味は変えない。明示海面がない世界で標高0を海と推定しない。
未知のポリシーは拒否し、保存復元では内容とworldIdを照合する。

## 表示までの接続

package-globe.mjs の --snapshot はポリシーを保存から読む。
新方式は通常の全球水面をページ参照から使い、旧方式では地域内だけの水面規則を保持する。
独立旧地域の外側は元の基礎場を参照する。旧単一地域/接続河川の外側が未知となる契約も保持する。
地域境界の数値が同じであることと、LODの細かさ・実画面の受入は別の検証。

## 実入力・実出力

npm run verify:shared-water は5つの生成世界の実際の湖岸に二つの小地域を設け、
それらの内側・外側・間の隙間を含む81点ずつ（計405点）を測定する。
元の全球場、地域付きCore、保存復元、ページ参照の地盤・水面・水深と水域IDを比較する。
各世界で濡れた点と乾いた点の両方を必須とし、湖内だけの一致に限定しない。
実際の入力・出力と最大差は examples/planet/verification/shared-water-shores.json。
今回の最大差は約4.7e-12m。これは指定した標本の一致で、連続空間全域の証明ではない。

## 境界と残る事項

- 基礎世界に明示した水域が対象。任意の旧地域ポリゴン同士を自動統合しない。
- 湖の水量・水位の時系列変化、堤体破壊、波、流速の連続解を追加したものではない。
- 旧地域の三角形河床を新しいC1河床へ黙って変更しない。
- 地域の掘削域同士の重複制約は維持する。共通の湖を参照する許可を、地盤の矛盾する
  重複編集の許可として使わない。
- 新規惑星の通常ビューは既に全球水面を参照していた。今回は多地域コア/API側にも
  同じ方式を明示的に接続し、保存とページ側の解釈のずれを解消した。
