# 全球Paged Globeの動作検証（0.4.0）

> この文書の数値・保留事項は上流0.4.0時点の履歴です。現在の自動水域・集落・LOD・保存の実装と最新検証は [PLANET_WORLD.md](PLANET_WORLD.md) / [ROADMAP.md](ROADMAP.md) を参照してください。旧GPU測定を現在のクラウド実装の性能証明として使いません。

実装と設計書は納品済みのプロトタイプ。数値試験、実画面、性能、長時間・端末・利用者の受入を分けて扱う。常時30fpsとブラウザ全体512MiB〜1GiBの受入を、平均fpsや管理バッファの上限だけで完了にしない。

**2026-10-10更新:** 基礎地形の誤差判定と階層順の双方向モーフを実装した。現在の証拠は [GLOBE_LOD_QUALITY.md](GLOBE_LOD_QUALITY.md)。全279試験、旧40保存再開、120秒平均99.17fps・p95 20.6ms・33.3ms超1回を記録した。以下の0.4.0初期測定は変更前の履歴であり、現在のコードの測定値ではない。

## 保存した証拠

`examples/globe/0.4.0/validation/` に次を保存する。

- `verification.json`: 初期測定時のコードのSHA-256、全試験、ページ検証、ブラウザとCoreの照合、地表格子間隔、品質ゲート。
- `stage3.log`、`build.log`: 数値回帰・旧保存・構文/入口の検証ログ。
- `runtime-final-120s.json`: 最終構成の自動連続移動。フレーム間隔・メイン処理・Long Tasks・遅いフレーム・管理メモリ推移・GPU・表示LOD・Workerキャッシュ・頂点標本を含む。
- `runtime-baseline-120s.json`: 補修前の参考測定。最終構成の証拠と混同しない。
- `settled-coverage.json`: 地表へ近づいた後の中心付近の表示タイルとCore標本。
- `globe-local.jpg`、`globe-metres.jpg` と対応するDOM記録: 同じ3Dページの局地・メートル視点。2026-10-10の引き継ぎ確認時点で、全球視点の `globe-space.jpg` と対応DOMは未保存。宇宙視点を含む移動記録は `runtime-final-120s.json` を参照する。

## 数値・互換・入力

全270試験が成功した。35 Coreモジュールを読み込み、30旧入口のexport同一性と8 Globeモジュールの構文を確認した。従来の旧40snapshotを元のworldIdと標本値で再構築し、原ソース8件・旧入力40件のSHAが変化していないことを確認した。実生成の全球2世界・8chart・2304中心・4144河川標本・672表面フレーム、および実地域2件の保存再開も一致した。記録は [第3段階の検証JSON](examples/audit-0.3.3/0.4.0/verification.json)。

新しい試験は、常駐/ページHermiteと全球詳細化の同一環境内の完全一致、極/経度境界、500地点と旧詳細化90地点、2実生成世界の水系、明示河川・橋・敷地、ページ破損・キャンセル、Float32精度、保守的高さ範囲、LRU解放、階層/要求上限、Cube辺両側の詳細化、細い地物下の地盤細分を確認する。

ブラウザは完全snapshotをfetchせず、サイズとSHAを検証したFloat64LEページと必要なフィーチャーを読む。デモは131072セル、512標高ページ。実生成packは各4chartを含む。pack全体の標高/フィーチャー533ファイルを再照合する。ツアー中128標本と静止後3標本の計131ブラウザ頂点、および中心点を、Nodeで再構築したCoreへ照合する。同じNode内の配列/ページ完全一致と、異なるNode/Chromium間の丸め許容を区別する。

最終構成のこの120秒では全フレームが33.3ms以内だった。補修前・途中の別構成では数十〜数百msの間隔も記録している。原因を確定して全環境で解消したとは扱わず、反復・長時間・端末差の受入を継続する。LODの生成待ちには親タイルを表示し、メートル格子の証拠は静止後のもの。移動中に常にこの格子間隔まで追従したという記録ではない。

120秒の経路は同じ球面シーンで宇宙→15m→局所パン→高度を確保した大域移動→宇宙を2回繰り返す。大域移動は日付変更線と北緯約89.9度を通る。初期読込10秒は測定の外。視界外タイルの削除と再読込はカウンタとメモリ時系列へ記録する。停止後に地表スライダーを操作して中心付近の格子間隔を確認する。

`performance.memory.usedJSHeapSize` はWindowのJS heapであり、Worker heap・GPUドライバ・ブラウザプロセスの全体測定ではない。Workerアンカーとフィーチャーの項目予算も実heap測定ではない。GPUバッファ64MiB、標高ページ各256KiB、アンカー各128KiB、フィーチャー各8MiB推定、Worker 2本、転送待ち4枚という管理上限を設定した。

## 再実行

パッケージで `npm run ui` を実行し、`/src/globe/index.html?benchmark=auto` を開く。10秒後から120秒の連続移動を実行する。画面の「動作検証記録」からJSONを保存し、`examples/globe/0.4.0/validation/runtime-final-120s.json` とする。地表で取得した `#coverage` のJSONを `settled-coverage.json` として保存する。

`npm run verify:globe` は全試験/第3段階の回帰とビルドを行った後、保存したブラウザ証拠の時刻・元world・Core標本・ページSHA・管理上限を照合する。自動でブラウザ測定を代行するコマンドではない。最新の回帰を再使用するときは `node scripts/verify-globe.mjs --reuse-stage3`。コード変更より古いブラウザ証拠は拒否する。

**ロードマップの現在位置は第5段階の全球表示プロトタイプ・数値一致・限定した実測。次は厳密なLODと視覚品質、長時間・端末・メモリの受入。**
