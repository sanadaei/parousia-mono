# 0.3.3分析への対応（0.3.4）

更新日: 2026-10-09。添付分析の幾何・詳細化・全球水系の指摘を実装と照合し、以下を修正した。湖・海・内陸終端湖の自動化は利用者の指定で保留を維持する。既存の出典管理対象ソースは変更しない。

| 対象 | 変更と契約 |
|---|---|
| 同一エッジ内の自己重複 | 同一エッジの湿潤三角形同士の、数値許容差を超える正面積の重なりを全構築方式で拒否。等水位の自己交差も検出する。隣接面の共有辺は面積0なので受理。新規構築と旧方式を含む保存復元の両方で検査 |
| 外岸の接続 | 影響率tをS(t)=t²(3−2t)で合成。Sの両端の微分が0になり、外岸で基礎地形の法線方向微分へ接続する。地表を持ち上げず、元の水面profileと深さを維持。内部三角形・中心線・屈曲点・合流/min合成の全C1化は未完 |
| 格子線/極域の詳細成分 | anchored-spherical-residual-bands@2を追加。球面Cartesianノイズから元セル中心のノイズの周期Hermite/極域cap補間を差し引き、半分にする。中心値を保ち、格子線全体や極域で成分を消さない。振幅の合計以内。旧方式の四隅の標高範囲とは異なる契約 |
| 複数の明示chart | connectGlobalSurfaceWaterChartsを追加。全球水系@2に1～16の独立chartを保存し、一つのsourceWorldIdと基礎samplerを共有。構築/復元でchartごとの球面場の再構築を省く。元のchart座標・profile・流域出典を維持。未知範囲は水深null。重複範囲・chartを跨ぐ接続は拒否 |
| 掘削検査の参照重複 | 保守的な線分上限の評価中に頂点の最大値も収集し、復元時の別の地表参照ループを除去。線分上限と頂点診断は別の検証として維持 |
| 保存互換 | 旧detail@1・水系construction@1/@2/@3・全球水系@1を同じworldIdと値で復元。新方式は別worldId。旧検証資料を版別の出力で保護 |

## APIと近似の範囲

```js
import { connectGlobalSurfaceWaterCharts } from './global-water.mjs';
import { createProjectedTerrainView } from './global-terrain.mjs';

const world = connectGlobalSurfaceWaterCharts(baseGlobal, {
  charts: [
    { id: 'basin-a', centerLatDeg: 0, centerLonDeg: 180,
      bounds: metricBoundsA, verticalDatum: baseGlobal.frame.verticalDatum,
      riverGraph: callerGraphA, waterBodies: callerBodiesA },
    { id: 'basin-b', centerLatDeg: 30, centerLonDeg: 0,
      bounds: metricBoundsB, verticalDatum: baseGlobal.frame.verticalDatum,
      riverGraph: callerGraphB, waterBodies: callerBodiesB },
  ],
});
const view = createProjectedTerrainView(world, callerViewContract);
```

chartは一意のidを持つ。同じ投影では矩形が離れ、別投影では矩形を包含する球面円が離れていることを検査する。差分距離の2倍を超える隙間を必要とする。円による保守的な拒否はあり得る。重複を順序で上書きしたり、異なる水面を暗黙につないだりしない。返却地点はwaterChartIdを持ち、waterSourceIdsはURL符号化したchart ID / source IDで識別する。

同じ投影軸のchartは、そのviewの線分/道路診断へメッシュ・探索域・既知範囲境界のイベントを追加する。別投影のchartとの交差は有限間隔の参照の精度に留まる。複数chartを持つことと、chartを跨いで一つの大河川を連結することは別の契約。

詳細化の新方式はfromGeographyLiteの新規読み込みで既定となり、detailMethodで旧bounded-spherical-bands@1も指定できる。createGlobalTerrainへのmethod省略は旧契約のまま。保存されたmethodを変更せずに復元する。基礎標高は従来の四隅の範囲を維持し、新しい詳細成分は総振幅で制限する。合成標高が局所四隅の範囲を超えることはあり、元の流向/流域は再計算しない。地質や実測微地形を追加した機能ではない。

新しいノイズの勾配上限はCartesianノイズとアンカー補間/極域capの両方から計算し、全球水系のLipschitz検査に加える。極点の基礎標高は元の行の平均のまま。元入力に極点の観測セルがないため、元セル・流域・地物の分類は極点で未定義のままにする。

## 分析の説明を補正する点

- 滑らかな影響率を掛けるだけでは、三角形内のlevel/depthやmin合成の勾配の不連続は消えない。今回の保証は外岸の接続。法線/曲率は固定距離の差分推定であり、基礎C1だけからC2や解析的な曲率を保証しない。有限の差分値が大きくなることを数学的な発散と同一視しない。
- minmodが極値で微分を0にすることは、山頂付近が一定値の台地になることの証明ではない。滑らかな極値も微分0を持ち、Hermite曲線はその周囲で変化する。視覚的な平坦化の受入には描画を要する。
- 格子線/極域で旧詳細成分が0になる指摘は正しい。基礎場全体が平面になることや、実際に溝/氷河が描かれることは未検証。極点の未知分類へ任意の元セルを割り当てると、経度依存の偽の出典を作る。
- 外周半セルは法線方向の一定延長で、接線方向の地形変化まで0にしない。独立した有限書き出しを継ぎ目なく接続する契約は未完。
- 書き出し後の水系入口はconnectSurfaceWaterであり、表流水/地下水格子と明示graphを接続する実例を0.3.3で検証済み。fromDynamicRegionalWaterは旧world固有の一次流向入力を要する。元流域をreferencesに保持することを局地の再計算済み水文だとは扱わない。
- 分流の拒否は任意のStrahlerサイジングに限る。通常の有向非循環graphは分流を扱う。流量/流速/季節/背水の物理解法とFlow Map用APIは未実装。
- 元の掘削検査は線分全体の保守的上限と頂点診断で、同一の条件ではなかった。今回、地表の頂点参照を共有して両検証を維持した。
- 多角形内部・接触・線分区間・領域切り取りの幾何ルーチンは役割が異なる。距離・面積・無次元の許容差を一つの定数へまとめることは行わない。数値/窓検証の残る重複、型定義、非同期化は保守性の課題として残す。
