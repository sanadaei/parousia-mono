# 集落規模とL1からL2への候補受け渡し

2026-10-13。全球の人口統計を、参照した地域だけの集落候補へつなぐ段階。
対象環境は **PC**。マウス・キーボード操作とPCブラウザーでの表示を対象にする。
人口正本は `planAgriculturePopulation`。L0/L1分布とは別の人口計算を作らない。

## 規模の仮定

新人口は `agriculture-population@2` とし、`population.sizePolicy` を規模仮定の正本として保存する。
既定の平均は村300人・町4,000人・都市50,000人。村には100人未満の小集落も含み、個別表示では小集落と区別する。
町の下限は1,000人、都市の下限は25,000人。各上限は平均の1.5倍。
町になれない比例配分人数は村側へ戻し、セルの総人口と食料容量は変えない。
都市は地域の人口と適性の順位を使い、安定したhashから仮の規模を選ぶ。
農村比率は目標値であり、最小規模・整数丸め後の実際の比率とは区別する。

L0→L1では集落の個数を面積・適性で配った後、親の一集落あたりの整数基本人数と余りを
その個数に結び付ける。人数を再び面積で独立配分し、極小の町を作ることを避ける。
親＝全子＋未配分は、総人口・村人口・町人口・都市人口・村数・町数・都市数の全7項目で検査する。

個別候補の人数には整数基本値と余りに、固定周期のゼロ和ペア変動を加える。
全候補を生成せずに人数のprefixを計算でき、ページや参照順を変えても人数・ID・原点は変わらない。
これは仮の規模ばらつきモデル。歴史的な較正、交易圏、都市階層の完成ではない。

## 地域の受け渡し

- `createL2SettlementHandoff(l1, population, cellIndex)`：L1の1セルを、7整数予算・地理境界・親区画・規模仮定・農地需要のコンパクトなレシピへ。
- `validateL2SettlementHandoff(handoff)`：版・内容ID・整数予算・規模の実現可能性・格子と地理的親・農地需要を照合。hashを付け直した算術や境界の矛盾も拒否。
- `readL2SettlementCandidatePage(handoff, {offset, limit})`：都市→町→村の固定slot順で、最大256件。等面積緯度の層化候補原点。座標は未調査の候補で、敷地・建物を作らない。
- `createL1SettlementSurveySurface(l1)`：保存されたL1高さの双線形補間とセル水域マスクを使う、識別付きの広域選別面。
- `surveyL2SettlementCandidates(surface, population, handoff, {offset, limit})`：既存集落サーベイの水域・標本勾配・既存集落との距離条件を再利用し、候補採用・立地保留・このページでは未調査の7予算を分ける。

農地は親の `netFoodKg / cultivatedHa` と `foodKgPerPersonYear` から求める必要耕地面積。
全候補の需要面積和は地域の整数m²需要と一致する。非正収量で正人口がある場合は未解決を明示する。
面積は土地の取得・適地の存在・造成・農業区画の確保を意味しない。

広域条件を通過した候補にも、L2の詳細地形、水源・洪水、敷地、生活圏・農地・接続道路の確認が残る。
画面は地域の境界と候補点を表示し、詳細地形を作った表示にしない。

## 再現と保存

```powershell
npm run l2:baseline
# 出力先や人口・seed・L1解像度を変える場合
npm run l2:baseline -- reports/my-l2-baseline --seed=planet-2 --population=100000000
```

出力先は `reports/l2-settlement-baseline`。L0/L1の実データ、L0概要、全球分布画面、
代表地域の候補ページ、`manifest.json`、`summary.json`、独立した `review.html` を保存する。
このCLIは代表地域の先頭・次・末尾などの限定ページを確認用に保存する。
coreのページAPIは、任意の妥当なL1セルから候補を取り出せる。

`saveL2SettlementCandidateSurvey` は既存の `CommittedMaterializer` と原子的ファイル保存を使う。
同じ保存ページを再参照するとサンプラを再実行せず、初回の候補選別を返す。
保存条件にはhandoff ID・選別面ID・L1レイヤーID・ページ範囲を含め、地形の変更を同じ保存へ黙って上書きしない。
候補レコードの上限は1MiB、L1の上限は従来の24MiBを維持する。

新しい生成と規模仮定には新しい人口・分布・候補IDが付く。旧統計例を新しいL2レシピとして使う場合は再生成する。
通常の生成キャッシュ版も更新した。旧保存世界や形状優先の地域ドラフトへ家屋・集落を自動追加する変更ではない。

現在のロードマップは **L0統計・L1配分から、規模付きの地域候補とL2への受け渡しまで**。
次は候補に対するL2詳細地形の立地調査、実際の敷地・農地・接続道路の統合。
全球の家屋生成、水文・食料経済、長時間運用、PCのGPU実機での受入は別の残件。
