# 地形コア ロードマップ（terrain/）

更新: 2026-10-14。旧実装（リポジトリ直下・`src/`）は参考として凍結し、地形の土台を `terrain/` に新しく作る。
使用先のエンジンは未定のため、生成部分はエンジンに依存しない型付き配列とし、ブラウザでプレビューする。

## 原則

1. **一つの生成過程を全縮尺で使う。** 惑星から近景まで、隆起と河川侵食（stream power）、斜面拡散を同じコードで実行する。縮尺ごとに別の作り方をして、それを契約でつなぐ方式はとらない。
2. **親が低周波を、子はその下の帯域だけを持つ。** 子を生成するときは、低域を数ステップごとに親へ合わせ直す。これにより、子を縮小すると必ず親に戻る。
3. **受け入れは縮尺の比較で判断する。** 惑星、400km、40km、4km、それ以下の同じ視点の画像を、実際の地球と比べて採否を決める。数値の検査は高度分布、傾斜分布、水系密度、Hackの法則などに絞る。
4. **見えないものを先に厳密にしない。** 水理、車両、暗渠などは、ゲームで必要になった時点で扱う。

## 段階

### T0 地形の骨格（完了: 2026-10-14、初版）
- L0惑星: 立方体球（N=512で約20km/セル）に、ゆがめたボロノイによるプレート、収束・発散境界、大陸地殻、大陸棚・海溝・海嶺の海底地形、緯度帯と内陸度による降水、120ステップの侵食を適用。所要約50秒。
- 詳細化: 親のサンプラーから512²の子領域を作る。余白付きで生成して中央を切り出し、低域を親に固定し、平坦地の流向には揺らぎを入れる。
- 比較ツール: `zoom-ladder.mjs` で、惑星→400km→40km→4kmを出力する。

### T1 地形の仕上げ（進行中）
**済（2026-10-14）**
- **大河の受け渡し**: 子の外周を親の流れの向きで「流出口」と「壁」に分け、壁側では親の上流の流量を流入点に注入する。本流が子の領域を通り抜けるようになった。
- **谷の始まり**: 集水面積が約4000m²に達するまでは谷を刻まず、その上流の斜面は拡散で丸く仕上げる。
- **限界勾配付近の拡散**: 限界勾配に近いほど拡散を強め（Roering型）、尾根を丸める。
- **細かい縮尺の時間幅**: 細かい縮尺ほど侵食の時間幅を短くし、起伏が際限なく育つのを防ぐ。
- **近景を解析的に計算**（`src/detail.mjs`）: シミュレーションはL2（約78m）までとする。それより細かい部分は、L2のなめらかな補間に、斜面に沿って長く伸びる溝のノイズ（オクターブを重ねて枝分かれさせる）と、L2の水系から引いた蛇行する川（スプライン、川幅と深さ、氾濫原）を加える。画素の大きさに応じて細かいオクターブを省くので、モアレが出ない。GPUへ移しやすい純関数で書いている。
- 縮尺比較は惑星→400km→40km→4km→0.4kmの5段階。地点は `mountain` と `hills` の2つ。

**判明したこと**
- 8m格子で侵食シミュレーションを回すと、縞模様や洗濯板状の模様になる。親の低周波に合わせ直す処理と侵食が競合し、実質的な隆起として働くため。
- 結論として、8m程度の細かい縮尺は解析的に作るほうが安定する。

**残り**
- **山地の近景**: 4km程度の縮尺で、岩の露頭・崖錐・雪渓の細部が足りず、ぼやけて見える。急斜面にだけ尾根状のノイズで岩を加えるか、L3を「刻むだけ」のシミュレーションでタイル生成する案を比べる。上から見た陰影図は粗が目立ちやすいので、評価はT2の3D表示で行う。
- **隣接タイルの継ぎ目**: 立方体の面の座標でタイルのキーを決め、重なり部分を混合する。面の境界でも正しく標本化する。
- 海岸の細部、湖（氷河湖・構造湖）、氷河地形、卓越風と雨陰。
- 受け入れ条件: 平野・丘陵・山地・海岸・乾燥地の5地点で縮尺比較を行い、実際の地形と比べて大きな違和感がないこと。

### T2 3Dプレビュー
- 立方体球の四分木タイルを、Workerでその場生成してストリーミングする（WebGL2）。
- 法線による陰影、大気散乱、空気遠近。縮尺比較用のカメラプリセット。
- エンジン向けの書き出し（16bit高さとメタJSON）。描画の判断は、担当表に従いGUI・グラフィック担当へ渡す。

### T3 土地被覆
- 気候と地形（傾斜、流量、標高）から、森林・草地・湿地・岩場・雪の分布を縮尺ごとに矛盾なく作る。生態の遷移帯も含める。

### T4 人の景観（近景を含む）
地形と水系から立地を決める。旧実装の人口分布（L0/L1）と、地形に沿った近隣配置（terrain-led）の考え方を再利用する。
- **集落の立地**: 段丘、合流点、渡河点、海岸の湾、交易路の結節点。人口予算はL0/L1から受け取る。
- **道路網**: L1で集落間を結ぶ最小コスト経路（傾斜、渡河、迂回を考慮）。L2で峠と谷道、L3で村の道と街路。
- **村・町・都市**: 等高線と水へのアクセスに沿った街路、敷地、建物、周辺の農地（傾斜と排水に合わせた区画）。
- **地形の編集層**: 道路と敷地の切り盛りを、生成した地形の上に重ねる編集層として持つ。生成結果そのものは書き換えない。
- 受け入れ条件: 村・町・道路を、地域・村・街路の縮尺で実例（航空写真・地形図）と比べる。

### T5 ゲーム統合
- 決定論的な再生成、タイルキャッシュ、LODストリーミング、保存（seedと編集層）、エンジンへの書き出し。

## 再現手順

```
node --max-old-space-size=2048 terrain/tools/build-planet.mjs planet-1 512
node --max-old-space-size=2048 terrain/tools/zoom-ladder.mjs planet-1-N512 [mountain|hills|lat lon]
```

出力は `terrain/out/` に置く（惑星の全体図、各縮尺の画像、惑星のバイナリとメタJSON）。
