# 引き継ぎ: 地形コア（terrain/）

更新: 2026-10-15（6回目: 未着手だったアセット（目印の建物、水辺と舟、作物、道路）を追加）。次のインスタンスは、この文書と [ROADMAP.md](ROADMAP.md) から作業を始める。

## 1. 目的とユーザーの要望

- ゲームで使える惑星と地形の生成器を作る。**惑星から足元まで、どの縮尺で見ても本物らしく見えること**が最重要。
- 近景の村・町・道・農地もロードマップに含める（ROADMAP T4）。
- 使用するエンジンは未定。生成部分はエンジンに依存させず、プレビューはブラウザで行う。開発・利用環境はPC。
- 旧実装（`../src/` などリポジトリ直下）は**参考として凍結**し、`terrain/` に地形の土台を新しく作ると、ユーザーが決めた。
- これまでの失敗。同じ失敗を繰り返さないこと。
  - 1つ目のモデル: 画面では見えない水理・暗渠・車両などを厳密にしすぎて、地形そのものがノイズのままだった。
  - 2つ目のモデル: 速いが、縮尺ごとに別の作り方（L0のノイズ／L2の「川を描いて周りを彫る」方式）をとっていた。300kmから55mの間に地形の情報がなく、どの縮尺でも作り物に見えた。

## 2. ユーザーの作業規約（`~/.claude/CLAUDE.md` の要点。リポジトリには含まれない）

- v1.0未満では、後方互換を維持しなくてよい。壊した場合は報告する。

  - 難しい実装・設計 → 司令塔（Codex `gpt-6.1-sol` high が基本）

### 4回目: 溝の樹状化と岩（`src/detail.mjs`）、影、比較ツール
- **樹状化**: 最初のオクターブを親のセル幅（78m、従来は39m）から始め、谷を長く（長さ係数1.6、探索窓7×7セル、窓の端で重み0）、前のオクターブの谷の側壁の向きへ強く曲げる（`gullySteer = 2.5`、高さには効かず向きだけ）。細かい谷が太い谷へ流れ込む。これで起伏が増えすぎたため、深さ係数0.11、オクターブごとの減衰を0.78にした。
- **岩**: 親の傾斜が0.4を超える所に、ゆるやかなノイズでまだらな岩場を置き、尾根状ノイズ（2乗、オクターブごとに平均を引く）で岩の凹凸を足す。`sample()` が `rock`（0〜1）を返し、色付けで岩色を混ぜる。
- **結果**（残差RMS / 傾斜p90 / p99）: forest-mountain L3 1.99m / 0.84 / 1.19、L4 0.41m / 1.26 / 2.80。hills L3 1.46m / 0.68、L4 0.16m / 0.65。継ぎ目の検査は比1.0。
- 試した案（`gullyScale`, `gullyLen`, `gullyWin`, `gullySteer` は引数で変えられる）: 窓と長さだけ（A）はまだ毛並み状。最初のオクターブを粗く（B）すると谷網になる。さらに向きを強く曲げる（C）と合流が良くなる。Cのまま深さを変えないと、L4の傾斜p99が4.9になり起伏が過大だった。
- **プレビューの影**（Sonnetに委任）: 太陽方向の正射影シャドウマップ（2048²、3×3 PCF、傾斜に応じたバイアス）。直射光の項だけを影で減らす。頂点シェーダーの共通部分を1つの文字列にまとめ、影の描画と本描画がずれないようにした。URL `shadows=0|1` とチェックボックス。影の範囲は注視点の周りの視距離の1.5倍なので、低い太陽では遠くの影が切れることがある。
- **`tools/montage.mjs`**（Haikuに委任）: 複数のPNGを格子状に並べて1枚にする（比較用）。`node terrain/tools/montage.mjs out.png 列数 a.png b.png ...`

### 3回目: 近景の溝ノイズの作り直し（`src/detail.mjs`）
- **数値の診断**: 細かい起伏（5セル平均からの残差のRMS）が、L2の自己相似な外挿（L2の値×0.1^0.75〜0.85）に比べてL3で約4分の1しかなかった（forest-mountainでL2 17.0m → L3 0.62m、期待値は約2〜3m）。傾斜もL3のp99が0.53〜0.78で、実際の山地の8m DEMより緩い。
- **変更**: 正弦波の縞をやめ、特徴点1つにつき斜面方向に伸びる**V字の谷1本**（幅・深さ・長さはランダム、出現はゆるやかなノイズで群れる）にした。谷どうしが接する所に鋭い小尾根ができる。オクターブごとに平均を引いて親の低周波を保つ。深さは**親（L2）の傾斜**に比例させた（1.5乗、上限あり）。変化する傾斜で深さを決めると、溝が溝を深くする正帰還になったため。傾斜の向きは従来どおり更新し、枝分かれさせる。
- **結果**（残差RMS / 傾斜p90）: forest-mountain L3 1.83m / 0.78、L4 0.21m / 1.08。mountain L3 1.21m、hills L3 1.33m。継ぎ目の検査（`probe-seams.mjs`）は比0.9〜1.0のまま。
- パラメータ: `createNearField(R, { gullyDepth = 0.16 })`。

### 3回目のその他（サブエージェントに委任した実装を含む）
- `tools/export-heightmap.mjs`（Sonnetに委任）: シーンから段ごとに16bitグレースケールPNG（その段の最小〜最大で線形量子化）、メタJSON（`terrain-heightmap@1`、`height_m = minH + value * heightScale`）、色PNGを書き出す。往復誤差が量子化幅の半分以内であることを検査済み。`tools/png.mjs` に `writePng16` を追加。
- 地点 `forest-mountain`（Haikuに委任、閾値は私が修正）: 標高900〜2600m、緯度25〜42度、降水0.45以上。この惑星では南緯39.8度・西経154.1度。標高約2000mで年平均気温は約2℃なので、色は高山帯（森林限界付近）になる。候補がないときは例外を出す。
- プレビューの「L3 low」プリセットを少し高く（距離0.6、俯角12度）した。手前の丘で視界が塞がれるため。

### 2回目の作業で直した不具合（後方互換なし。出力が変わる）
1. **惑星の侵食で陸の53%が深さ5m超の湖になっていた**（`src/erosion.mjs` の `routeFlow`）。平坦地に付ける傾き（イプシロン）を `2e-5 * distScale` で決めていたが、惑星では `distScale` が半径（6371km）なので1セルあたり約127mになっていた。辺の実長（m）×2e-5（最小2mm）に直した。湖は5%に減り、地図はコミット済みの旧画像とほぼ同じ見た目に戻った（HANDOFF §6.4の精度対策を入れたときに混入したと推定。旧画像はその前の生成と思われる）。
2. **近景の溝ノイズに格子状の段差**があった（`src/detail.mjs`）。斜面方向に長い核（約2.4セル）を3×3セルだけで探していたため、セル境界で特徴点が出入りして高さが跳んでいた。境界での段差は他の場所の18〜33倍。5×5セルを探し、半径2セルで0になる重み（taper）を掛けて解消した（比0.9〜1.2）。
3. **細い川が点線・穴の列になっていた**（`src/detail.mjs`）。川幅が標本間隔より狭いと、川の掘り込みがとびとびに当たる。川幅を標本間隔の3倍まで広げ、断面積を保つ（浅くする）ようにした。水と見なすのは本来の川幅が占める割合（`waterCover`）が0.5以上のときだけで、それ未満は色を混ぜる。

## 5. 再現手順（Node 22以上）

```
node --max-old-space-size=2048 terrain/tools/build-planet.mjs planet-1 512        # 約65秒、出力 terrain/out/
node --max-old-space-size=2048 terrain/tools/zoom-ladder.mjs planet-1-N512 hills  # 約35〜60秒
node --max-old-space-size=2048 terrain/tools/zoom-ladder.mjs planet-1-N512 mountain
node --max-old-space-size=2048 terrain/tools/export-scene.mjs planet-1-N512 mountain  # 約60秒、8MiB
node terrain/tools/serve.mjs     # → http://127.0.0.1:8787/preview/?scene=planet-1-N512-mountain
node terrain/tools/shoot-scene.mjs planet-1-N512-mountain 1,2,3,4,5,6   # 任意。Playwrightが必要
node terrain/tools/export-heightmap.mjs planet-1-N512-mountain             # エンジン向け16bit PNG
# 地点: mountain / hills / forest-mountain / 緯度 経度
```

- `terrain/out/` はgit管理外。上の手順で再生成できる。
- プレビューの操作: ドラッグで回転、右ドラッグ/Shift+ドラッグで移動、ホイールで拡大縮小、1〜6で視点プリセット（L1, L2, L3, L4, L3低視点, 地上）、Hでパネル。URL引数 `preset, exag, sunAz, sunEl, haze, ui=0`。
- 入れ子の表示: 親は子の範囲を描かず、子は外周8%を親の高さと傾きに寄せ（geomorph）、外周にスカートを垂らす。カメラから各段の幅の2倍以上離れた段は描かない（細かい起伏のエイリアス防止）。
- 2回目の作業はクラウドのLinuxコンテナ（Node 22.22、メモリ16GiB、開始前の空き約15GiB）で行った。Cドライブ・G:ドライブは存在しない環境。ピークメモリは未計測。重い処理は1つずつ実行した。起動したChromiumとサーバーは各実行の終わりに閉じた（残存プロセスなしを確認）。
- 担当表のCodex/OpenCodeはこの環境で使えないため、2回目はグラフィックを含めすべて自分（Claude）で実装した。3回目以降はユーザーの指示で、簡単な実装をSonnet（16bit書き出し、影）とHaiku（地点の追加、比較画像ツール）に委任した。設計と近景の改良は自分で行った。

## 6. 試して分かったこと（同じ失敗を繰り返さないために）

1. **8m格子での侵食シミュレーションは失敗した**（縞模様・洗濯板状・多面体状の模様）。親の低周波に合わせ直す処理と侵食を交互に行うと、実質的な隆起として働き、起伏が限界勾配まで育つ。細かい縮尺では時間幅を短くした（`dt *= 1-0.9*fine`）が、それでも不十分だった。**約78mより細かい部分は計算式で作る**方針にした。
2. 窪地を残すと湖だらけになる。`lakeFill=1` で埋めたうえで、深さ3m未満の窪地は平らにする。湖はT1で意図して作る。
3. 外周をすべて流出口にすると、水が任意の場所から抜けて本流が途切れる。流出口と壁に分けて解決した。
4. float32の精度: 標高2000mでは、平坦地に付ける傾き（イプシロン）が精度の刻みより小さくなり、流れ先が消えてNaNになる。イプシロンの最小値を2mmにし、さらに窪地を埋めたときに通った経路の前のセルを予備の流れ先にした。
5. 近景の溝のノイズ: 位相を乱数にすると隣の点と干渉して虫食い状になる。斜面に沿って長い楕円の重みと、位相を揃えた形にした。また、L2のD8・限界勾配による格子の痕跡は10倍に拡大すると見えるため、1セル程度のぼかしを掛けてから補間する。ぼかしを強くするとぼやける。
6. 真上から見た陰影図は粗が実際以上に目立つ。山地の近景の最終判断は3D表示で行う（T2）。
7. 逆に、真上の陰影図では見えない問題が3Dで見える。規則的な溝ノイズは斜めから見ると波紋・砂丘に見え、格子の段差は点線状の穴に見えた。採否は3Dのスクリーンショットでも確認すること。
8. 地図用の川の塗り（流量の閾値を超えたセルを青くする）は、3Dでは781m幅の階段状の帯になる。3D用の書き出しでは川幅÷セル幅の被覆率で色を混ぜる（`colorize(..., { rivers: 'coverage' })`）。
9. `mountain` 地点は南緯47度・標高1700〜2000mで、気温が低くツンドラ色になる。高木限界より上の山地としては妥当だが、森林のある山地を見るには別の地点（緯度を下げる）を `lat lon` で指定する。
