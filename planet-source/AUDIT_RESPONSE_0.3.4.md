# 0.3.4監査への対応（0.3.5）

添付分析の優先事項である実装の分岐とUIの判定差を補修した。第3〜5段階の機能を全体として完了したとは扱わない。湖・海・内陸終端湖の自動化は利用者の指定で引き続き保留する。

## 今回の変更

- 同名の18ファイルが同一内容で複製され、`index.mjs` は参照先、`water-model.mjs` は河道の境界接触情報に差があった。この20ファイルを転送入口に変え、既存10入口も含む30入口を `src/core` へ統一した。新しい境界接触検査を保持した。ビルドは全エクスポートの同一性を検査し、再分岐を拒否する。
- 通行性UIはコアのクラス・通行可否・移動費用を表示する。歩行は勾配0.5まで、よじ登りは1まで、車両は0.3まで。渡渉水深は歩行者0.3m・車両0.4mまでで、境界を含む。地図の色は歩行者の要約で、インスペクターには両移動種別を出す。未知の水深はnullのまま。コアの道路面を参照し、橋面の冠水や急勾配を一律に通行可能扱いしない。道路・敷地の図形でこの判定色を上塗りしない。仮設サンドボックス図形は提案表示として描く。
- 交差UIはコアの4状態を保持する。平面一致、離隔確保、離隔不足、衝突を色・カード・地図警告へ反映した。既定の車両離隔4.5m、橋桁厚0.5m、平面一致許容差1e-7mを共有する。寸法不明のレコードを平面一致へ変換しない。旧UIの状態名は読み取り互換の別名として受ける。
- UIで導出する交差位置はコアで検出し、縦断はコアの三次曲線で評価する。密な縦断標本を平面の別線分として総当たりしない。正確な節点では同じ区間と演算順を選び、離隔閾値付近の丸め差を避ける。水域交差の出典がある橋だけを水域橋として集計する。
- シーンの保存が交差・暗渠レコードと付加情報を落としていたため、元のシーン契約を保って保存するよう修正した。シーン保存は入力と診断の保持であり、サンドボックスの全編集履歴や全表示状態の永続化の完了を示さない。
- UIの球面距離・方位を `src/core/spherical.mjs` へ移した。7本の検証スクリプトは実行・メモリ確認・SHA-256・JSON出力を共有する。子プロセスは256MiB、30秒、直列、開始時の空きメモリ768MiB以上。通常試験と全verifierは同じ全試験一覧を使う。参照のない `.uitest.mjs` と `.uitest2.mjs` を削除した。

## 分析中の説明を補正した点

外岸でsmoothstepの微分が0になることは、地表全体の傾きが0になる意味ではない。合成は `G=B+S(T-B)` なので外岸の `S=0, S'=0` で `∇G=∇B` となり、傾いた基礎地形にも接続する。内部三角形、屈曲点、合流やmin合成のC1化は引き続き未完。

地下水役割の格子は数値の地下水位を保存・参照する。ダミー0ではないが、Darcy流や季節変動は実装しない。海も明示した水域と水位を入力する静的モデルであり、標高0を海面とする自動化はしない。D8の1/√2距離は直交/対角方向の距離差で、これ自体が誤りではない。8方向への離散化の偏りは残る。

## ロードマップの現在位置と残課題

**現在は第3段階の残課題と、第4・第5段階の統合検証が進行中。今回の実装統一・UI整合の優先補修は完了。**

| 段階 | 実装・確認済みの範囲 | 残る範囲 |
| --- | --- | --- |
| 第1・2段階 | 共通sampler、保存契約、静的な明示水系 | 物理水文・自然さの校正。水域自動化は保留 |
| 第3段階 | 全球/投影、残差詳細化、明示chart間河川、固定細分D8補正の数値コア | chart間の明示水域接続、全河床C1、補正後の実生成多seed受入、大域の整合 |
| 第4段階 | 道路/建物造成、交差・離隔・通行性、重力排水候補の数値コア | 造成後の流向/流域と実際の暗渠・滞水モデルの連動、道路全幅/車両掃引域の離隔、構造耐力、横断勾配 |
| 第5段階 | Web表示、今回のコア判定との一致、限定した実画面と保存再開 | 実生成地域の通し操作・自然さ・端末性能・利用者受入、全編集状態の永続化 |

次の優先対象は造成後の排水連動。現行の `inspectEarthworkDrainage` は通水経路の候補診断で、水系samplerへ管や滞水を構築する機能ではない。固定細分D8補正も水系を重ねる前の基礎全球地形を対象とし、造成後の全域再計算ではない。解析上限262,144セルと奇数細分1..15の契約を保持する。明示水域のchart間接続を進める場合も、水域の自動同定とは区別する。
