# 居住適性と広域集落ネットワーク

## 現在できること

新規seed生成に広域計画を保存する。標準128地点、最大512地点。詳細集落は標準8、最大32。
詳細集落のID・座標をそのまま広域計画へ取り込み、追加地点は建物なしの候補として保持する。
カメラ・LOD・表示順によって位置や経路を作り直さない。世界の保存IDには広域計画も含む。

全球画面の「居住適性と広域の道の候補を見る」で、色分けされた2D地図と経路・地点一覧を確認する。
旧保存世界にデータを捏造せず、不在と表示。更新サーバーで新たにseed生成すると作成される。
CLI: node scripts/generate-planet.mjs my-seed new-output --sites=128 --settlements=12

## 評価

陸地のみ。広域近隣勾配45%、標高30%、モデル上の河川・湖への距離25%。0〜100。
勾配8%で勾配点が0、海面から4000mで標高点が0、水距離は100kmを尺度に指数減衰。
これらの重みと尺度は明示的なゲーム設計上の仮定。気候的な居住可能性ではない。
海・湖セルは除外。候補間の最小間隔は80km、スコア35以上・緯度±65度以内（既存生成と同じ仮の緯度制限、気温の代替推定ではない）。要求数は上限で、条件不足なら少なくなる。
飲用可能性、降雨、気温、土壌、生産量、資源、政治制度、局所洪水は未評価。

## 道の候補

各地点の近隣3地点への組を作り、東西周期境界つきの四近傍グリッドで最小費用探索。
海・湖セルと広域勾配12%超の遷移を除外。距離・勾配・標高に応じて費用を増やす。
到達できない組は未接続として記録。海を直線で渡る陸路や勝手なフェリーは作らない。
全地点の連結保証や歴史的な街道網の最適化は未実装。

## 解像度とLOD

128×64の地球サイズの元データは数百km級。これは広域回廊の仮説であり、細かい海岸・崖・河川を越えない保証ではない。
メートル単位の通行可能な道路・峠・橋・町の敷地は次段階の局所調査が必要。
追加候補を見ただけで建物を作らないため、512候補でも512町分のメッシュを生成しない。
ただし候補から詳細集落をオンデマンドで実体化する処理はまだ未実装。今は指定数の詳細集落を生成時に作る。

## 再現性

同じseedと件数・生成版をキーに保存版を再利用。異なる件数は別の出力先。
旧seed生成プロファイルv1はそのまま残す。今回v2へ更新。

## 実入力・実出力による確認
seed=network-example-1、広域128地点、詳細12集落:
128地点（詳細12+未実体化116）、233ルート、接続不可11組。
同じ保存世界から再計算し、保存復元後の計画とdeepEqualで一致。
同じ地形で512地点を要求すると512地点・908ルート。128/512の計画再計算を合わせて約0.66秒、終了時JSヒープ約65MiB（クラウド上の1実測、生成全体やピーク値ではない）。

既存の詳細集落は、粗いセルでは水域になる場合もある。位置を勝手に移動・消去せず保持し、そのセルからの陸路は未接続として残す。局所的に乾いた敷地が確認済みでも、広域セル評価が良いとは限らない。局所と広域の接続改善は残件。
