# 月別気候とバイオームの実装状況

2026-10-10。CLIMATE_BIOME_DESIGN.md のA+Bと、雨頼み農業・人口・選定の初期接続。

## 使い方

更新後に npm start でサーバーを起動し直す。seedから新しく生成し、全球画面の「気温・降水・バイオームを見る」を開く。
気温・降水は年と12か月を切替。地図クリックで同じセルの月別数値を確認できる。
潜在バイオームと既存水系の注意箇所も切り替えられる。
古い保存世界はデータ不在と表示し、勝手に気候を補わない。seed出力プロファイルはv4。

## 実装

- 地球型の緯度・標高・海陸性・季節による月平均気温。
- 海からの湿潤供給、卓越風の帯、地形上昇と雨陰を64回の同時更新で近似した月降水。
- 年集計、面積、潜在バイオーム、既存の川/湖との乾燥地域の不整合候補。
- 世界保存に含め、気候ページは別ファイル。比較画面で必要なときだけ読む。
- 保存ページのbyte数、SHA256、気候IDを照合。

## 未完成と仮定

降水のmmはモデルの尺度であり、物理的水蒸気保存や気象予測の精度を保証しない。
湿気輸送は東西方向の近似で、南北輸送・海流・モンスーン・実測土壌・細かい植生混合は未実装。
潜在植生は実際の森林、耕地、木の配置とは異なる。全球3Dは標高・潜在バイオーム・気温・農業・人口のレイヤーを切替可能。
新しい生成版は気候を農業適性・人口容量・集落候補に利用する。詳細は以下。
川・湖の位置や流量は気候生成によって変えない。乾燥地域の川は上流からの供給で成立しうるため、注意表示は矛盾の確定ではない。
季節の年周期時計との完全接続は未実装。3Dの太陽緯度スライダーは照明検査で、気候月を変更しない。

保存時に負のゼロが通常の0へ変わる差を検出し、丸め時に0へ統一。JSON保存前後の一致をテストで確認する。


## 農業・人口・集落選定（追加実装）

planet-population.mjs。LLMなし、8192セルの地域集計。標準人口は1億人。
1. 各月5〜35℃を生育可能月とし、その月の降水を集計。5か月・450mmを充足の目安とするゲーム上の仮定。
2. 緩斜面率×面積×耕作率15%でhaを求める。土壌倍率1は明示した仮定であり、土壌を実測・生成した値ではない。
3. 穀物800kg/ha/年×気温・降水充足率×収穫留保55%を食料とする。1人250kg/年換算で人口容量。
4. 指定人口を容量比例で整数配分。容量不足は未配分として残し、無理に1億人を押し込まない。
5. 都市人口予算を地域人口内で集中させ、町・農村へ残りを配分。全階層の人口合計は地域人口と一致。
6. 村300人・町4000人・都市50000人という仮定から個数を推定。これらは地域ごとの集計値であり、全件の位置・道路・建物生成ではない。
7. 詳細集落の敷地候補を農業適性0.1以上・人口のある地域へ絞り、適性で順位付け。広域候補の地形得点にも農業適性を乗ずる。

この例は雨頼み穀物経済だけ。交易、灌漑、漁業、牧畜、政治、人口移動は未実装。
農地の個別区画や森林伐採、全30万村の座標、都市の街区規模はまだ生成しない。
建物まで生成する集落は最大32、広域の座標候補は最大512。地域推計の村数とは別。
世界を眺めたりレイヤーを変えても、人口・位置・IDを再計算しない。
旧世界は保存内容のまま。generatePlanetの既存利用は互換動作、climatePlanning:trueで接続し、通常のseed生成CLIはこれを有効化する。

## 地図表示

全球3Dの「地図レイヤー」で潜在バイオーム・年/月気温・農業適性・人口密度を切替。
気候と人口ページは必要時に一度だけ取得し、byte数・SHA256・IDを検査。
GPUは128×64 RGBAテクスチャ1枚を使い回す。CPU診断も同じセルの色を参照。表示切替は地形メッシュや集落を再生成しない。
気温の月切替は気候平年値の閲覧であり、ゲーム内の時間進行ではない。
等高線は100/500/1000m間隔で表示中のメッシュの標高から描く。海面上の地形のみ、道路/水面オーバーレイには描かない。遠方の精度はLODに依存し、測量図ではない。

### 検証の範囲

クラウドChromeのCPU診断描画で、全球バイオーム、気温1月→7月、500m等高線、農業、人口、再読込後の固定集落IDを確認。
このクラウドChromeではWebGL2が利用できず、WebGL実画面の検証は未実施。GPU用シェーダー経路は実装したが、実機GPUでの視覚/性能確認は残る。
気候ページ1,718,522 bytes、人口ページ1,949,898 bytes（上記seed）。8192地域の集計で、30万村分のオブジェクトを保持しない。
保存からの復元と同じ入力からの人口再計算が一致。寒冷/無降雨で人口不足を隠さないこと、人口の各階層の総和、人口0なら集落を選ばないことを自動検証。

総人口は生成画面の「要求する総人口」またはCLI --population=100000000 で指定。seed・候補数・詳細数・人口から別保存先を決める。
