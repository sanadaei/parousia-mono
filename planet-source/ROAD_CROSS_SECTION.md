# 道路の横断形状と雨水

## 今回接続したこと

generator @15 の新しい道路は、中央から両端へ 2% 下がる横断形状を持つ。
幅6mなら中央と端の高低差は6cm。これはゲーム内の舗装路向けの明示プリセットであり、
全地域・未舗装路に共通の自然法則や実設計基準ではない。

保存する定義は road.crossSection（road-cross-section@1）一つ。
Core の造成地盤、車輪が参照する道路面、描画メッシュ、道路間の高さ判定が共用する。
地盤を使う既存の雨水移送もこの形状を読む。見た目だけ傾ける処理ではない。

- crownSlope: 中央から両端へ下がる勾配
- crossSlope: 左を正とする片勾配。今回の自動生成は0。明示入力は扱える
- flatIntervals: 交差点・既存の平坦な橋面の区間
- transitionLengthM: 平坦区間から横断勾配へ滑らかに戻る長さ（生成値12m）

縦断中心線は従来の正本を保つ。横断標高差は片勾配×横距離−冠勾配×横距離の絶対値。
平坦区間へは三次 smoothstep の積で移行する。中心線の尖った冠形状は意図的な折れ線で、
道路全域の C1 曲面とは主張しない。曲がり角の旋回片勾配の自動設計も行わない。

## 相互整合

交差点は幅全体が同じ高さとなる区間を保存する。既に横断形状がある道路を再設計する場合も
その区間を追加する。平坦な梁・床版として保存した橋には、異なる冠形状を後付けできない。
表示は冠の中心で三角形を分割し、横断形状の変化を含めて縦方向の5mm補間誤差上限を計算する。
道路間のクリアランスは横断高低差を含む保守的な高さ区間で判定する。

## 互換性

crossSection が無い旧保存は従来通り平坦。復元時に自動挿入しない。
新しい生成でも API roadCrownSlope:0 または CLI --road-crown=0 で平坦を明示できる。
新規生成の revision は @15。既存の @14 以下の保存を上書きしない。

## 検証と限界

単体検査では両端/中心の高さ、交差点の一致、保存/復元、実メッシュ頂点、
冠上の降雨が両側へ移動すること、水収支、平坦橋との不整合拒否を扱う。
5mの雨水格子では幅6mの道路を十分に分解できない場合がある。
細かい格子での単体確認を、現在の村全体の格子が全排水を再現する証拠としない。
交差点と橋面は平坦で、側溝・集水ます・橋面排水口・浸透/舗装材・侵食は未生成。
水の運動量を解く流体シミュレーションや道路工学上の安全認証でもない。

## プリセットの参考

FHWA の Interchange Design Promptlist では舗装面の横断勾配2%が例示される。
https://highways.dot.gov/field-offices/missouri/interchange-design-promptlist

未舗装路は別条件。FHWA の Unpaved Road Dust Management 第6章には4%未満の冠勾配の
滞水への注意があり、今回の2%をそのまま未舗装路の基準とする根拠にはならない。
